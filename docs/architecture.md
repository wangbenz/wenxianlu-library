# 文件资料服务架构

本次接口、启动和配置的完整说明见根 [README](../README.md)。本工程是独立资料服务，不修改游戏工程。

`Git JSON → Schema → 引用/阶段/交叉校验 → 不可变内存快照 → 只读 API`。FastAPI lifespan 在接受请求前完成加载，错误拒绝启动。运维重载在锁内构建候选，完整成功后一次替换；读取固定单个快照，失败继续服务旧版本。单 worker 运行，多副本不使用单次重载同步。

公开投影通过字段白名单构造；服务间读取和运维重载使用不同 Bearer 令牌。资料内容、指纹及索引不写数据库。资料库只提供最新定义，游戏端负责冻结本局完整采用内容；Git 保存资料历史。

移除的 Django 模型、管理后台、数据库迁移与历史接口没有兼容隐藏通路。旧游戏客户端尚未适配新路径和字符串 revision，因此不切换本地 8011 服务。回退使用原 `personal/main` 的独立运行方式及已有数据，不通过 JSON 服务反向写数据库。

迁移只读取旧 JSON 与明确审核的映射，复制新文件集到全新输出目录，不猜测语义，不访问旧数据库；文件输出不自动激活。完整旧资料内容与第一批新资料在格式审核后进入后续 PR。
